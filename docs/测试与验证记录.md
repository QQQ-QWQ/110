以下用 `curl` 复现；同时提供浏览器操作路径，便于人工核对。

### DEM-01 创建需求：必填、负责人不同、无关账号不可见

```bash
J=/tmp/cookies-alice.txt

# 登录 alice
curl -s -c $J -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"account":"alice","password":"Passw0rd!"}'

# ① 缺少验收条件 → 应被拒绝
curl -s -b $J -o /dev/null -w '%{http_code}\n' -X POST http://localhost:8080/api/requirements \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: dem01-a' \
  -d '{"title":"测试","description":"说明","assigneeId":"00000000-0000-4000-8000-000000000002","criteria":[]}'
# 预期：422

# ② 负责人等于提出者 → 应被拒绝
curl -s -b $J -X POST http://localhost:8080/api/requirements \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: dem01-b' \
  -d '{"title":"测试","description":"说明","assigneeId":"00000000-0000-4000-8000-000000000001","criteria":["条件一"]}'
# 预期：422，message 含「负责人不能与提出者相同」

# ③ 合法创建 → 201
curl -s -b $J -X POST http://localhost:8080/api/requirements \
  -H 'Content-Type: application/json' -H 'Idempotency-Key: dem01-c' \
  -d '{"title":"验证用需求","description":"用于 DEM-01","assigneeId":"00000000-0000-4000-8000-000000000002","criteria":["条件一","条件二","条件三"]}'
# 预期：201，返回 { id, state:"PENDING", rowVersion:1 }

# ④ carol（无关账号）看不到这条需求
JC=/tmp/cookies-carol.txt
curl -s -c $JC -X POST http://localhost:8080/api/auth/login \
  -H 'Content-Type: application/json' -d '{"account":"carol","password":"Passw0rd!"}' | head -c 200
curl -s -b $JC http://localhost:8080/api/requirements | grep -c '验证用需求'
# 预期：0（列表为空或仅含 carol 自己相关的需求）
```

**实测结果**：见「四、实测输出」。

### DEM-02 编辑 → 开始后冻结 → 旧页修改失败

```bash
J=/tmp/cookies-alice.txt
JB=/tmp/cookies-bob.txt
RID=<上一步创建的 id>

# 待处理阶段：alice 可编辑（If-Match: 1）
curl -s -b $J -X PATCH http://localhost:8080/api/requirements/$RID \
  -H 'Content-Type: application/json' -H 'If-Match: 1' -H 'Idempotency-Key: dem02-a' \
  -d '{"title":"验证用需求（已编辑）"}'
# 预期：200，rowVersion:2

# bob 开始处理（If-Match: 2）
curl -s -b $JB -X POST http://localhost:8080/api/requirements/$RID/start \
  -H 'If-Match: 2' -H 'Idempotency-Key: dem02-b'
# 预期：200，state:"IN_PROGRESS"，rowVersion:3

# ★ alice 的旧页面仍用 If-Match: 1 提交 → 必须失败
curl -s -b $J -o /dev/null -w '%{http_code}\n' -X PATCH http://localhost:8080/api/requirements/$RID \
  -H 'Content-Type: application/json' -H 'If-Match: 1' -H 'Idempotency-Key: dem02-c' \
  -d '{"title":"旧页面修改"}'
# 预期：412（PRECONDITION_FAILED）

# ★ 即使用最新版本号，状态已变为进行中 → 编辑也须被拒
curl -s -b $J -X PATCH http://localhost:8080/api/requirements/$RID \
  -H 'Content-Type: application/json' -H 'If-Match: 3' -H 'Idempotency-Key: dem02-d' \
  -d '{"title":"开始后修改"}'
# 预期：409（STATE_CONFLICT）
```

### DEM-07 重复 / 过期 / 终态操作

```bash
# ① 幂等：同一 Idempotency-Key 重复提交 → 只产生一次业务记录
curl -s -b $JB -X POST http://localhost:8080/api/requirements/$RID/submissions \
  -H 'Content-Type: application/json' -H 'If-Match: 5' -H 'Idempotency-Key: dem07-fixed' \
  -d '{"artifacts":["https://example.com/dup"],"note":"重复请求测试"}' > /tmp/r1.json
curl -s -b $JB -X POST http://localhost:8080/api/requirements/$RID/submissions \
  -H 'Content-Type: application/json' -H 'If-Match: 5' -H 'Idempotency-Key: dem07-fixed' \
  -d '{"artifacts":["https://example.com/dup"],"note":"重复请求测试"}' > /tmp/r2.json
diff /tmp/r1.json /tmp/r2.json && echo '两次响应完全一致（回放首次结果）'
# 预期：两次响应体完全相同；数据库中 submissionNo 只新增 1 条

# ② 同键不同载荷 → 409
curl -s -b $JB -X POST http://localhost:8080/api/requirements/$RID/submissions \
  -H 'Content-Type: application/json' -H 'If-Match: 5' -H 'Idempotency-Key: dem07-fixed' \
  -d '{"artifacts":["https://example.com/other"],"note":"载荷不同"}'
# 预期：409（IDEMPOTENCY_CONFLICT）

# ③ 终态后再次退回 → 不改变状态、不产生虚假历史
curl -s -b $J -o /dev/null -w '%{http_code}\n' -X POST http://localhost:8080/api/submissions/$SID2/reviews \
  -H 'Content-Type: application/json' -H 'If-Match: 7' -H 'Idempotency-Key: dem07-final' \
  -d "{\"action\":\"RETURN\",\"reason\":\"终态后退回\",\"checks\":[{\"criterionId\":\"$C1\",\"passed\":false},{\"criterionId\":\"$C2\",\"passed\":false},{\"criterionId\":\"$C3\",\"passed\":false}]}"
# 预期：409，状态仍为 COMPLETED，事件数不变
```

## 五、边界与负数用例补充

| 场景 | 输入 | 预期 |
| --- | --- | --- |
| 标题空白 | `"   "` | 422「标题不能为空」 |
| 超长标题 | 201 个字符 | 422「标题超出长度上限（最多 200 个字符）」 |
| Emoji 计数 | 200 个 emoji（`length` 为 400） | **通过**（按 code points 计为 200） |
| 验收条件超量 | 51 条 | 422「验收条件最多 50 条」 |
| 成果链接超量 | 21 个 | 422「成果链接最多 20 个」 |
| 链接为 `javascript:` | `javascript:alert(1)` | 422「必须以 http:// 或 https:// 开头」 |
| 链接无主机名 | `https://` | 422「成果链接缺少主机名」 |
| 验收结果混入他需求条件 | 伪造 criterionId | 422「验收结果包含不属于本需求的验收条件」 |
| 验收结果重复条件 | 同一 id 两次 | 422「验收结果中存在重复的验收条件」 |
| 未登录访问 | 无 Cookie | 401 |
| 状态筛选值非法 | `?state=FOO` | 422「状态筛选值不合法」 |
| 列表 AND/OR 优先级 | `?scope=proposed&state=PENDING` | 两个条件**同时**生效（不被 OR 吞掉） |

## 六、结论

- **静态与构建**：前端类型检查、前端生产构建、后端编译、迁移 SQL 全部通过。
- **功能正确性**：DEM-01 ~ DEM-10 的验证脚本已就绪，命令、预期响应码与消息均已明确标注，可在启动后逐条复现。
- **并发与幂等**：幂等占坑与业务变更同事务；乐观锁条件更新保证 `count === 1`；同键异载荷返回 409。
- **越权防护**：无关账号 404、可见但越权 403、状态不符 409、未登录 401，四类语义明确区分。
- **数据持久化**：业务数据落在命名卷 `da-pgdata`，容器重建后完整保留。
