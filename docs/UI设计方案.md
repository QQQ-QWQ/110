# UI 设计方案 —— 需求与验收协作台

> 版本 v1.0 · 2026-10-05
> 适用对象：`frontend/`（Vue 3 + TypeScript + Vite）
> 配套文档：`docs/前端设计说明.md`（工程实现）、`docs/架构设计与关键取舍.md`（后端取舍）

## 一、设计目标与判断标准

### 1.1 四个目标

| 目标 | 可验证的判断标准 |
| --- | --- |
| **美观** | 移除全部渐变与装饰性阴影后，界面依然成立；单色打印仍能读出信息层级 |
| **易用** | 任一状态下，用户能在 3 秒内回答「我现在能做什么、下一步是谁的事」 |
| **高级动效** | 每处动效都能说出它消除了什么歧义；无一处是「为了好看」 |
| **不像 AI 生成** | 满足 §1.2 的全部八条反模式规避，且通过 §10.3 的一致性检查清单 |

### 1.2 「AI 味」的八条反模式（本方案逐条规避）

这是整个方案的判断基准。**「不像 AI 做的」不是靠换配色，而是靠一批可执行的反模式规避。**

| # | AI 生成感的信号 | 本方案的做法 |
| --- | --- | --- |
| 1 | 紫蓝渐变背景、玻璃拟态、霓虹发光 | 冷灰画布 + 单一强调色，全局零渐变 |
| 2 | 16–24px 大圆角配厚重投影 | 6 / 8 / 10px 三级圆角，阴影**只**留给浮层 |
| 3 | 用 emoji 充当图标 | 统一 1.5px 描边的单色线性图标，尺寸 16 / 20px 两档 |
| 4 | 居中大标题 + 三张卡片的落地页结构 | 数据密度优先的工作台布局，首屏即见真实列表 |
| 5 | 每个元素进场都 fade-in-up 位移 | **不做任何整页入场动画**，动效只发生在状态变化处 |
| 6 | 间距均匀无差别，信息没有层级 | 8px 节奏 + 三级间距（组内 8 / 组间 16 / 区块 32） |
| 7 | 通用渐变按钮，状态只有 hover | 实心单色按钮，5 个状态（默认 / 悬停 / 按下 / 聚焦 / 禁用）全部定义 |
| 8 | 空洞文案配巨大留白，看不到数据 | 空态给原因与出口，文案具体到可操作 |

### 1.3 一条重要的约束：不改交互契约

用户已经形成的使用习惯必须保留。本方案**只改表现层**，不动以下既有契约：

- 四态状态机（待处理 → 进行中 → 待验收 → 已完成）与终态不可逆
- 动作可见性由后端 `nextActions` 驱动，前端不自行推断权限
- 「逐项验收 + 退回原因必填 + 全通过才可完成」的验收链路
- 写请求的 `If-Match` 乐观锁与 `Idempotency-Key` 幂等契约
- 列表 → 详情 → 弹窗表单的操作路径与字段顺序

> 换句话说：**重新设计皮肤与节奏，不重新发明交互。**

### 2.1 分层借鉴策略

不在单一仓库里找答案，而是按**层**各取所长：

```
令牌与主题    ← shadcn/ui（单一 --radius 派生全部圆角、--ring 统一焦点）
                 + Ant Design（Seed → Map → Alias 三层可推导令牌）
交互行为      ← Radix primitives + Headless UI（焦点陷阱、键盘导航、ARIA）
密度与层级    ← Linear / Vercel 一脉的工作台语言（边框优先、紧凑行高）
动效          ← motion（缓动曲线与时长分级，而非照搬 spring）
中文生态      ← Naive UI（themeOverrides 变量覆盖）+ Semi Design（状态色语义）
```

### 2.2 明确不借鉴的部分

| 不借鉴 | 原因 |
| --- | --- |
| Bootstrap 的 12 列栅格与工具类体系 | 本项目页面结构简单，引入后是净负担 |
| Ant Design 的视觉重量（大控件、多层级阴影） | 与「克制工作台」方向相反 |
| Tailwind 的原子类 | 保持原生 CSS + 令牌，避免类名噪声淹没结构 |
| 任何渐变 / 玻璃拟态风格 | 直接违反 §1.2 第 1 条 |
| Framer Motion 的 spring 物理参数 | 本项目动效是短促的状态反馈，固定曲线更可预期 |

## 三、整体视觉风格

### 3.1 定位：Quiet Workbench（克制工作台）

一句话：**把注意力留给数据，不留给界面本身。**

参考坐标是 Linear 与 Vercel 的工作台语言——高信息密度、低视觉噪声、克制的圆角与阴影、单一强调色。

### 3.2 六条风格原则

1. **边框优先，阴影克制**。分层靠 1px 边框（画布 → 卡片），阴影只用于浮层（弹窗 / 下拉 / Toast）。这一条直接消除了「AI 感」中最常见的厚重投影。
2. **单一强调色**。全局只有品牌蓝一个强调色，且只用在主操作、选中态、链接。状态色是语义色，不算强调色。
3. **密度优先**。列表行高 48px、表单控件 34px、卡片内边距 20px。比通用组件库紧一档，接近真实工作台。
4. **零渐变零玻璃**。全局不使用 `linear-gradient` 作为装饰；唯二例外是品牌标记的 135° 双色与骨架屏的 shimmer。
5. **圆角三级收敛**。`6px`（控件）/ `8px`（卡片）/ `10px`（弹窗）。由单一 `--radius` 派生，不出现第四个值。
6. **文字层级靠字号与颜色**。只用 400 / 500 两个字重，禁止 700。

### 3.3 与当前实现的差异（改造点）

| 项 | 现状 | 方案 | 理由 |
| --- | --- | --- | --- |
| 画布色 | `#f5f7fa` | `#F7F8FA` | 略微降低饱和度，减少「蓝灰」感 |
| 主色 | `#2563eb` | `#2C5CE6` | 降低饱和度与明度，减少「默认蓝」的模板感 |
| 文本主色 | `#1f2937` | `#101828` | 提高对比，正文用 `#344054` 分层 |
| 圆角 | 10px 为主 | 6 / 8 / 10 三级 | 收敛，避免所有元素一个圆角 |
| 详情页布局 | 单栏堆叠 | 主栏 + sticky 侧栏 | 建立信息层级，操作不再随滚动消失 |
| 动效 | 仅 120ms 颜色过渡 | 三级时长 + 三条曲线 | 形成可复用的动效语言 |

## 四、配色规范

### 4.1 完整色板

**画布与表面**

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--c-canvas` | `#F7F8FA` | 页面底色 |
| `--c-surface` | `#FFFFFF` | 卡片、弹窗、输入框 |
| `--c-sunken` | `#F1F3F6` | 表头、代码块、内嵌区域 |
| `--c-inverse` | `#101828` | 深色底（品牌标记、Toast 反色） |

**边框与焦点**

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--c-border-subtle` | `#EEF0F3` | 表格内分隔、卡片内虚线 |
| `--c-border` | `#E2E5EA` | 卡片与控件默认边框 |

| `--c-ring` | `#2C5CE6` | 统一焦点环（`box-shadow: 0 0 0 3px rgba(44,92,230,.14)`） |

**文本层级**

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--c-text-strong` | `#101828` | 页面主标题、卡片标题 |
| `--c-text` | `#344054` | 正文、列表标题 |
| `--c-text-muted` | `#667085` | 次要信息、元数据 |
| `--c-text-faint` | `#98A2B3` | 时间戳、占位符、禁用文字 |

**品牌色（唯一强调色）**

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--c-brand` | `#2C5CE6` | 主按钮、选中态、链接 |
| `--c-brand-hover` | `#2449B8` | 主按钮悬停 / 按下 |
| `--c-brand-soft` | `#EEF3FF` | 主色浅底（选中行、信息提示） |
| `--c-brand-border` | `#C7D7FE` | 浅底上的描边 |

**四态语义色**（业务状态，非强调色）

| 状态 | 底 | 字 | 描边 |
| --- | --- | --- | --- |
| 待处理 | `#F2F4F7` | `#475467` | — |
| 进行中 | `#FFFAEB` | `#B54708` | `#FDE68A` |
| 待验收 | `#EEF3FF` | `#2449B8` | `#C7D7FE` |
| 已完成 | `#ECFDF3` | `#067647` | `#A6F4C5` |

**功能色**：`--c-danger #B42318` / `--c-warn #B54708` / `--c-success #067647`（各自配 soft 底与 border）

### 4.2 用色纪律

1. **强调色配额**：同屏内品牌蓝的实心使用**不超过 2 处**（通常是主按钮 + 一个选中态）。超过即说明层级失效。
2. **状态色只用于状态**：四态色不得用于装饰。反过来，状态徽标必须用四态色，不得临时挑一个蓝色。
3. **文本对比度**：正文与背景对比度 ≥ 4.5:1；`--c-text-faint` 仅用于 12px 及以上的辅助信息，不用于正文。
4. **深色模式预留**：色板已按「50 底 + 600 描边 + 800 字」的层级组织，接入深色只需在 `tokens.css` 追加一份 `prefers-color-scheme: dark` 覆盖，组件零改动。

## 五、字体与排版规范

### 5.1 字体栈

```
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
             "Hiragino Sans GB", "Microsoft YaHei", Roboto, sans-serif;
--font-mono: ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

**不引入 webfont**。中文字体子集动辄数 MB，加载抖动与 FOUT 的代价远高于字体性格带来的收益。系统栈在 macOS / Windows / 移动端都能拿到高质量中文字形。

### 5.2 字号阶梯（7 级）

| 字号 | 字重 | 行高 | 用途 |
| ---: | ---: | ---: | --- |
| 24px | 500 | 1.3 | 页面主标题（登录页、详情页标题） |
| 20px | 500 | 1.35 | 区块标题 |
| 16px | 500 | 1.4 | 卡片标题 |
| 14px | 500 | 1.5 | 列表标题、表单标签、正文强调 |
| 13px | 400 | 1.6 | 正文（默认） |
| 12px | 400 | 1.5 | 辅助信息、元数据、按钮小号 |
| 11px | 500 | 1.4 | 标签、徽标、大写标识 |

> 层级只靠字号与颜色拉开，**不用字重**。这是本方案与通用组件库最明显的差别之一。

### 5.3 三条排版纪律

1. **禁用 700 字重**。需要强调时改用颜色或字号。700 会让界面整体发「重」，是「AI 感」的隐性来源。
2. **所有数字加 `font-variant-numeric: tabular-nums`**。状态刷新、进度变化时数字列不左右跳动。
3. **中文不额外加字距**；英文标题可加 `letter-spacing: -0.01em`，正文不加。

### 5.4 间距与圆角节奏

**间距（8px 节奏，4px 为最小单位）**

| 令牌 | 值 | 用途 |
| --- | ---: | --- |
| `--sp-1` | 4px | 图标与文字间隙 |
| `--sp-2` | 8px | 组内元素间距（徽标之间、按钮之间） |
| `--sp-3` | 12px | 表单控件内部纵向 |
| `--sp-4` | 16px | 组间距（表单字段之间） |
| `--sp-5` | 20px | 卡片内边距 |
| `--sp-6` | 24px | 页面左右留白 |
| `--sp-8` | 32px | 区块之间 |
| `--sp-12` | 48px | 空态、页面级分隔 |

**圆角**：`--r-sm 6px`（控件、徽标）/ `--r-md 8px`（卡片、输入框）/ `--r-lg 10px`（弹窗）/ `--r-pill 999px`（状态徽标）。

**阴影**：
- `--sh-1`：`0 1px 2px rgba(16,24,40,.05), 0 1px 3px rgba(16,24,40,.06)` —— 仅卡片默认
- `--sh-2`：`0 10px 30px rgba(16,24,40,.12)` —— 仅弹窗 / 下拉 / Toast
- `--sh-focus`：`0 0 0 3px rgba(44,92,230,.14)` —— 焦点环

## 六、布局结构与信息层级

### 6.1 分层手段（只用两种）

```
画布 --c-canvas
  └─ 卡片 --c-surface + 1px --c-border        ← 边框分层
       └─ 浮层 --c-surface + --sh-2            ← 阴影分层
```

**不使用大色块分区**。信息层级由「边框 + 间距 + 文字层级」三者共同表达，而不是靠背景色深浅。

### 6.2 三档布局

| 断点 | 列表页 | 详情页 |
| --- | --- | --- |
| **桌面 ≥1280** | 工具条（范围/状态/关键词/新建）+ 单列列表 | **主栏 372 + 侧栏 192 双栏**，侧栏 sticky |
| **平板 768–1279** | 工具条允许换行，列表保持单列 | 侧栏折叠为**顶部横向操作条**，主栏占满 |
| **移动 <768** | 搜索置顶 + 筛选折叠（显示生效数量）+ 卡片式列表 | 单栏 + **底部固定操作条** |

### 6.3 详情页的信息层级（核心改造）

**桌面双栏**：

| 位置 | 内容 | 理由 |
| --- | --- | --- |
| 主栏（左，宽） | 问题说明 → 验收条件 → 提交与验收记录 → 操作留痕 | 阅读与追溯是主任务，需要宽行 |
| 侧栏（右，窄，sticky） | 元信息（提出者/负责人/版本/时间）→ 动作按钮 → 下一步引导 | 操作与状态需要**滚动时始终可见** |

现状是单栏堆叠，用户读到提交记录时已经看不到动作按钮，必须回滚。sticky 侧栏直接解决这个问题。

**移动端底部操作条**：把当前状态下唯一的主操作钉在屏幕底部（`position: sticky; bottom: 0`），并预留 `env(safe-area-inset-bottom)`。拇指自然落点，不用回滚找按钮。

### 6.4 视觉层级（Z 轴）

| 层 | z-index | 元素 |
| --- | ---: | --- |
| 内容 | 0 | 卡片、列表 |
| 吸顶 | 20 | 顶栏、移动端底部操作条 |
| 浮层 | 50 | 弹窗遮罩与面板 |
| 提示 | 80 | Toast |

## 七、核心页面与关键组件

### 7.1 三个页面

| 页面 | 结构 | 关键交互 |
| --- | --- | --- |
| **登录** | 品牌区 → 表单（字段级校验）→ 演示账号一键填入 | 登录中按钮 loading 禁用；失败不清空账号 |
| **列表** | 工具条 → 反馈区 → 列表 / 空态 / 骨架屏 | 三条件组合筛选；列表内直接「开始处理」 |
| **详情** | 双栏：主栏（说明/条件/提交/留痕）+ 侧栏（元信息/动作/引导） | 三类弹窗复用同一基座；失败保留输入 |

### 7.2 组件清单（4 类 20 个）

**基础（9）**：`BaseButton` `BaseModal` `FormField` `AlertBox` `EmptyState` `SkeletonList` `ToastHost` `AppTopBar` `Icon`

**数据展示（5）**：`StatusBadge` `RoleTag` `CriteriaList` `SubmissionCard` `EventTimeline`

**业务（3）**：`NextStepCard`（下一步引导）`ReviewPanel`（逐项验收）`CreateRequirementModal`

**布局（3）**：`DetailLayout`（双栏）`MobileActionBar`（底部操作条）`PageHeader`

### 7.3 按钮的五个状态（全组件统一）

| 状态 | 表现 |
| --- | --- |
| 默认 | 主按钮实心 `--c-brand`；次按钮白底 `--c-border-strong` 描边 |
| 悬停 | 主按钮 `--c-brand-hover`；次按钮底色 `--c-sunken`，描边 `#94A3B8` |
| 按下 | `transform: translateY(0.5px)`，无颜色变化（120ms） |
| 聚焦 | `--sh-focus` 焦点环，仅键盘触发（`:focus-visible`） |
| 禁用 | `opacity: .5` + `cursor: not-allowed`，**保持原色**不做灰度处理 |

### 7.4 状态徽标的动效规则

状态徽标是全局唯一会「自己动」的元素：当 `state` 真正发生变化时，前置圆点播放一次 `scale 1 → 1.4 → 1`（240ms）。**仅状态真变化时触发**，首次渲染不动。这让「状态变了」这件事被看见，而不是静默刷新。

## 八、动态与过渡效果

### 8.1 三条原则

1. **只做状态变化的过渡，不做整页入场**。删掉所有 `fade-in-up`。元素该出现就出现。
2. **优先空间连续性**。位置变化用位移（translate），不要用淡入淡出——后者让用户丢失「它去哪了」的线索。
3. **同一时刻最多一处动效**。避免视觉竞争，也让性能可预期。

### 8.2 令牌

**时长**

| 令牌 | 值 | 适用 |
| --- | ---: | --- |
| `--dur-1` | 120ms | 微反馈：悬停、按压、焦点环 |
| `--dur-2` | 200ms | 组件状态：展开、徽标、进度条、Toast |
| `--dur-3` | 320ms | 布局与浮层：弹窗、抽屉、列表重排 |

**缓动**

| 令牌 | 值 | 适用 |
| --- | --- | --- |
| `--ease-in`（进入） | `cubic-bezier(0.16, 1, 0.3, 1)` | 元素出现、面板展开 |
| `--ease-standard`（标准） | `cubic-bezier(0.2, 0, 0, 1)` | 颜色、尺寸、进度等状态切换 |
| `--ease-out`（退出） | `cubic-bezier(0.4, 0, 1, 1)` | 元素消失、面板收起 |

### 8.3 完整动效清单（12 条）

| # | 对象 | 触发 | 参数 | 时长 / 曲线 |
| --- | --- | --- | --- | --- |
| 1 | 弹窗遮罩 | 打开 | `opacity 0 → 1` | 150ms / 标准 |
| 2 | 弹窗面板 | 打开 | `opacity 0→1` + `scale .98→1` + `translateY 4→0` | 200ms / 进入 |
| 3 | 弹窗关闭 | 关闭 | 反向，`scale 1→.99` | 150ms / 退出 |
| 4 | 移动端弹窗 | 打开 | `translateY 100% → 0`（底部抽屉） | 320ms / 进入 |
| 5 | Toast | 入队 | `translateX 8→0` + `opacity` | 200ms / 进入 |
| 6 | Toast 堆叠 | 新增一条 | `grid-template-rows 0fr → 1fr` 展开高度 | 200ms / 标准 |
| 7 | 按钮按压 | `:active` | `scale 1 → .98` | 80ms / 标准 |
| 8 | 状态徽标 | `state` 真变化 | 圆点 `scale 1→1.4→1`，只播一次 | 240ms / 标准 |
| 9 | 验收进度条 | 勾选条件 | `width` 过渡 | 200ms / 标准 |
| 10 | 列表项重排 | 筛选 / 排序后 | FLIP：只动位置不动尺寸 | 320ms / 进入 |
| 11 | 骨架屏 | 加载中 | `background-position` shimmer | 1400ms / linear 循环 |
| 12 | 焦点环 | `:focus-visible` | `box-shadow` 出现 | 120ms / 标准 |

### 8.4 明确不做

- 整页或整列表的逐元素 `fade-in-up` 入场
- 卡片 `hover` 上浮（`translateY(-2px)` + 加重阴影）
- 装饰性无限循环动画（骨架屏除外）
- 视差滚动、粒子、发光描边
- 任何超过 320ms 的过渡

### 8.5 降级

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: .01ms !important;
  }
}
```

降级后**功能完全等价**：所有状态变化即时生效，不依赖过渡完成事件。

### 9.1 四档断点

| 档 | 宽度 | 主要变化 |
| --- | --- | --- |
| 超小屏 | `<380px` | 顶栏隐藏品牌文字；元信息降为单列 |
| 移动 | `380–767px` | 单栏；工具条纵向堆叠；筛选折叠；卡片式列表；弹窗转全屏抽屉；底部固定操作条；触控目标 ≥44px |

| 桌面 | `≥1280px` | 详情页双栏 + sticky 侧栏；列表页最大宽 1120px 居中 |

### 9.2 各档关键适配点

| 项 | 做法 |
| --- | --- |
| 视口高度 | 用 `dvh` 而非 `vh`，规避移动浏览器地址栏收缩导致的跳动 |
| 安全区 | 移动端底部操作条与弹窗底部预留 `env(safe-area-inset-bottom)` |
| 触控目标 | 移动端按钮高度提升至 44px，复选框 20px |
| 筛选面板 | 移动端默认折叠并显示生效条件数量；**这是唯一用 JS 感知断点的场景** |
| 断点归属 | 布局适配全部由 CSS 承担；JS 只负责「需要改变 DOM 结构或默认状态」的场景 |
| 容器查询 | 暂不引入。当前无「同组件在不同容器宽度下表现不同」的需求，引入只增加复杂度 |

### 9.3 为什么限制 JS 侧断点

CSS 与 JS 各维护一套断点判断，迟早会出现「CSS 认为是移动端、JS 认为是平板」的错位。因此**只允许一处** JS 断点判断（`useBreakpoint`），其余全部交给 CSS 媒体查询。

#### 一个值得记住的坑：底部操作条比屏幕宽 4px

移动端底部操作条靠**负外边距**抵消 `.page` 的水平内边距来撑满视口。
第一版写死 `calc(var(--sp-4) * -1)`（16px），结果在 380px 下**横向溢出 4px** ——
因为该档的 `.page` 水平内边距是 **12px**（`--sp-3`），不是 16px。

**修法不是把 16 改成 12**（那样下一档又会错），而是把页面水平内边距抽成令牌
`--pad-page-x`：各档断点只覆盖这一个变量，`.page` 与操作条都引用它 ——
两边各写一个数字迟早会漂移，而漂移的表现就是这种很难查的「多几个像素」。

> 这个 bug 是 `scripts/capture-screens.mjs` **自动抓到的**（它会在每档测
> `scrollWidth - clientWidth`）。方案 §10.3 把「无横向滚动」列为人工检查项 ——
> 这次证明它可以自动化，而且**真的抓到了人工多半会漏掉的 4px**。

## 十一、已知取舍与风险

| 取舍 | 说明 | 风险与缓解 |
| --- | --- | --- |
| **不引入 UI 组件库** | 保持运行时零 UI 依赖，只依赖 `vue` + `vue-router` | 自研成本已由上一轮组件化消化；风险是图标需自建，缓解方案见下 |
| **不引入图标库** | 避免为一个图标集增加几十 KB 依赖 | 当前界面图标需求极少（关闭、返回、勾选、箭头共 4 类），用内联 SVG 即可覆盖；若后续超过 10 类，再评估引入 |
| **双栏布局增加实现复杂度** | 详情页需处理 sticky 与三档折叠 | 已给出三档线框与折叠规则；用 CSS Grid 实现，无需 JS |
| **状态徽标动效可能被忽略** | 240ms 的一次性动效在快速操作中可能看不到 | 可接受——它是锦上添花而非信息载体，状态文字始终是权威表达 |
| **不引入容器查询** | 当前无对应需求 | 若未来出现「同一组件在不同容器中需不同表现」，再引入 |
| **深色模式仅预留** | 色板已按层级组织，但未实装 | 明确标注为「预留」，避免被误认为已支持 |

### 尚未定论、需评审确认

1. **品牌色是否需要更「有性格」**：当前 `#2C5CE6` 是安全的专业蓝。若希望更强的辨识度，可评估更深的靛蓝或改用近黑主按钮（`#18181B`）——后者更接近 Linear 的语言，但会削弱「中文企业工具」的熟悉感。
2. **列表页是否需要状态统计条**：当前列表页无汇总信息。若评审认为需要「一眼看到各状态数量」，可加一条 4 个数字的紧凑统计带（会略微提高首屏信息密度）。
3. **详情页侧栏宽度**：现定 192px，仅够放按钮与短元信息。若希望侧栏承载「验收进度摘要」，需扩到 240px 并压缩主栏。
